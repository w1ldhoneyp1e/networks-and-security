## Архитектура

- В папке `socket/common` находятся переиспользуемые функции:
  - `ProtocolSendMessage()` и `ProtocolRecvMessage()` отправляют и получают сообщение целиком: имя и число. 
  - `ParseIntRange()` проверяет, что введённое число попадает в нужный диапазон
  - `LogErrno()` выводит сообщение об ошибке ОС.
- Клиент `socket/client/client.c`. Он получает число через `ClientReadNumber()`, подключается к серверу с помощью `ClientConnectToServer()`, отправляет имя и число, затем ждёт ответ. После ответа клиент выводит имена, оба числа и их сумму, после чего закрывает соединение.
- Главный поток сервера находится в `socket/server/server.c`. Он создаёт слушающий сокет и ждёт новые подключения через `epoll`. Когда подключается клиент, функция `AcceptConnections()` принимает его сокет и кладёт в очередь.
- Очередь из `queue.c` безопасно передаёт подключённых клиентов рабочим потокам. Сервер создаёт фиксированное число таких потоков, поэтому не создаёт отдельный поток для каждого нового клиента.
- Каждый рабочий поток выполняет `WorkerMain()` из `worker.c`. Он берёт клиента из очереди, ждёт его сообщение не более 10 секунд, выводит полученные данные, отправляет ответ и закрывает сокет. Если клиент прислал число вне диапазона `1..100`, поток запрашивает остановку сервера.
- `stats.c` считает активные подключения, количество запросов и среднее время их обработки. `control.c` помогает корректно завершить сервер по `Ctrl+C`: главный поток перестаёт принимать новых клиентов, а уже принятые соединения заканчивают обработку.

Тесты вынес в [TESTS.md](TESTS.md).

## Сборка

```bash
make -C socket
```

## Запуск

Сервера

```bash
./socket/server_app 5050 8
```

Клиента

```bash
./socket/client_app 127.0.0.1 5050
```

### Проверка корректного завершения

Клиент не позволяет ввести невалидное число, поэтому проверить корректное завершение через клиент можно,
запустив его с флагом --shutdown

```bash
./socket/client_app --shutdown 127.0.0.1 5050
```
