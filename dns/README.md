## Архитектура

- `dns/common/dns_packet.*` формирует DNS-запрос и разбирает заголовок,
  вопросы, ответы, authority- и additional-записи. Поддерживается сжатие имён
  DNS (compression pointers).
- `dns/common/udp_transport.*` выполняет один DNS-обмен по подключённому UDP-
  сокету с помощью `socket()`, `connect()`, `write()`, `read()` и `close()`.
- `dns/resolver/iterative_resolver.*` начинает работу с корневых серверов,
  обрабатывает referral с glue-записями и идёт к следующему серверу имён до
  получения нужной записи.
- `dns/client/main.cpp` разбирает аргументы и печатает только конечный ответ;
  флаг `-d` добавляет отладочную информацию в `stderr`.
- Интеграционные тесты в `dns/tests/run_tests.py` используют временный DNS-
  сервер на `127.0.0.1`, поэтому не выполняют внешних запросов.

Тесты вынесены в [TESTS.md](TESTS.md).

## Сборка

```bash
make -C dns
```

## Запуск

```bash
./dns/dns_resolver <domain> <type> [-d]
```

Примеры:

```bash
./dns/dns_resolver example.com A
./dns/dns_resolver example.com AAAA -d
./dns/dns_resolver example.com DNSSEC -d
```

`DNSSEC` является синонимом типа `DNSKEY`: программа
запрашивает запись, но не выполняет криптографическую DNSSEC-валидацию.

Дополнительные параметры `--root <IPv4>` и `--port <порт>` позволяют заменить
корневой сервер, например для локальных тестов. В обычном запуске они не нужны:
используется встроенный список IPv4-адресов корневых серверов и порт 53.

Работаем по UDP. При установленном флаге `TC` она завершаем
работу с понятной ошибкой;
