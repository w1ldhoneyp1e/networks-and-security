## Архитектура

- В `smtp/common/socket_connection.*` находится работа с TCP: создание сокета,
  подключение, полная запись буфера и чтение строк. Класс `Socket` гарантирует
  закрытие дескриптора при выходе из области видимости.
- В `smtp/common/smtp_reply.*` разбираются SMTP-ответы, включая многострочные,
  и проверяются ожидаемые коды: `220`, `250`, `251`, `354` и `221`.
- `smtp/message/email.*` читает текст письма из файла, формирует заголовки
  `From`, `To`, `Subject`, переводит окончания строк в CRLF и экранирует точку
  в начале строки по правилам SMTP (dot-stuffing).
- `smtp/client/smtp_client.*` реализует последовательность протокола:
  `EHLO`, `MAIL FROM`, `RCPT TO`, `DATA`, передача письма, `QUIT`.
- `smtp/client/main.cpp` проверяет аргументы, создаёт письмо, подключается к
  серверу и запускает SMTP-диалог.
- Интеграционные тесты находятся в `smtp/tests/run_tests.py`: они поднимают
  временный SMTP-сервер только на `127.0.0.1` и не отправляют реальные письма.

Тесты вынесены в [TESTS.md](TESTS.md).

## Сборка

```bash
make -C smtp
```

## Запуск

Сначала создайте файл с текстом письма, например:

```bash
printf 'Hello, SMTP!\n' > message.txt
```

Затем запустите клиента:

```bash
./smtp/smtp_client <server> <port> <from> <to> <subject> <message-file>
```

Пример для локального SMTP-сервера:

```bash
./smtp/smtp_client 127.0.0.1 2525 alice@example.test bob@example.test 'Test letter' message.txt
```

Для ручной проверки в отдельном терминале можно поднять готовый локальный SMTP-
сервер:

```bash
python3 -m aiosmtpd -n -l 127.0.0.1:2525
```

Клиент реализует обязательную базовую часть задания. TLS, авторизация и MIME-
вложения в него намеренно не включены: это дополнительные части лабораторной.
